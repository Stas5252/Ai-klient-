# Известные проблемы и исправления

Обновление 09.10.2026: в коде исправлены просроченные уведомления, вопросы после отмены, потеря бюджета/канала и ложная готовность Threads по одному токену. 147 тестов прошли. Код пока не опубликован в Worker. Billing 403 и риск CPU остаются открытыми; ниже исторические и прочие ограничения.

## Исправлено и проверено

- Маркетинговые задачи со словом «сайт» попадали в веб-лиды — исключение по направлению задачи, regression tests.
- Любой «подрядчик/сотрудничество» превращал заказ в партнёрство — только явное регулярное веб-партнёрство.
- Диапазон бюджета превращался в максимальную цену — budget/budgetMax/budgetKind, не обещаем точную стоимость.
- Подозрительный текст попадал в черновик — черновик блокируется, исходник остаётся untrusted evidence.
- Одинаковые заявки разных клиентов сливались — отдельный ключ chat + originating start.
- Сбой между шагом опроса и вопросом терял вопрос — session/outbox atomically batched.
- Удаление оставляло owner copies/raw inbox — transactional deletion по subject_contact + direct SQL, без лимита первых 1000.
- /stop можно было обойти /health — suppression до ветки commands и перед delivery.
- XML parser обрабатывал весь feed — bounded extraction без полного XML дерева.
- Квота считала jobs вместо HTTP — budgeted fetch на каждом actual attempt, atomic D1 counter.

## Открытые эксплуатационные проблемы

- Free Worker CPU10ms: production сбор72ms, повтор+аудит38ms, cron+3 отправки21ms, повторный cron со сбором36ms. Outcomeok не доказывает устойчивость: Cloudflare может прекратить регулярные превышения. Требуется разделение/профилирование.
- OAuth не даёт Billing Read (/subscriptions403). Bootstrap нового пустого аккаунта не является authoritative проверкой тарифа, повторный deploy guard не разрешает fallback для созданных ресурсов.
- Ошибки сети после отправки Telegram могут означать доставку; unknown не replay, вручную проверить. Telegram API не имеет idempotency key.
- DNS rebinding не исключён на 100%; не использовать runtime с доступом к приватной сети.
- SLA/24x7 абсолютной доступности на Free нет.

## Ограничения реализации

- `/export` сейчас инструкция к защищённому API, не выгрузка Telegram-файлом.
- Нет браузерных проверок forms/cart/JS/layout, автоматического поиска официальных сайтов по всему интернету, доказательства отсутствия сайта, outbound adapter, личного Telegram-аккаунта, VK/Threads auth.
- Уже доставленные сообщения Telegram сохраняются у получателя; `/delete_me` очищает хранимые системные копии и очередь, но не обещает удалить чужой чат/скачанный экспорт.
- Регистрация самозанятого, бесплатность и срок отклика каждого тендера требуют проверки.
- Открытый репозиторий не содержит CRM; production данные находятся в закрытой D1, локальные проверочные SQLite исключены из git.
