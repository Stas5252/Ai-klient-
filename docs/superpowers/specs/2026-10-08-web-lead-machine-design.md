# Web Lead Machine — спецификация

Основание: подробное ТЗ пользователя. Пользователь разрешил самостоятельные технические решения, реализацию, отдельный репозиторий и бесплатное развёртывание. Повторное согласование архитектуры не требуется. Основной сайт и чужие репозитории не меняются.

## Цель и границы
Автономный поиск актуальных веб-заказов, партнёров, подтверждённых проблем сайтов; частная CRM; Telegram уведомления и сценарий входящих. Нет порога бюджета. Нет покупки API, прокси, тарифа или расходуемых платных кредитов. Реальные данные отделены от тестовых.

## Архитектура
TypeScript Worker с cron */15 * * * *, D1 для leads, source_state, events, inbox, notification_outbox, inbound_sessions, settings, audit_jobs, suppression. SQLite-миграции. RSS сборщики, явно разрешённые источники отдельно от технически достижимых. FL.ru RSS — реально проверенный стартовый кандидат; бесплатность отклика неизвестна. Другие источники включаются только после проверки.

Collectors → normalizer → validator → deduplicator → scoring → CRM → notification outbox. Входящие webhook → durable inbox → rules manager → CRM → owner notification. Только известные команды интерпретируются; тексты публикаций никогда не исполняются. Полный журнал не содержит токенов или переписки.

## Контакт
Бот уведомляет только владельца и отвечает пользователю, первым начавшему диалог. Нет адаптера отправки холодных сообщений или отправки от личного Telegram-аккаунта. Очередь хранит черновики и отдельные разрешения/согласия; одобрение черновика само по себе не даёт права отправки. Получатели не выбираются из текста модели. Отписка /stop, удаление /delete_me, suppress перед любым разрешённым контактом.

## Безопасность и ограничения
Webhook header secret, числовой whitelist admin, административный API Bearer secret; ссылки только http(s), без credentials, приватных IP и localhost. Аудит GET, robots.txt, без форм, корзинных действий и защищённых страниц, лимит ответа 256 KiB, timeout 8 s, no redirect. Ошибки сети помечаются неопределёнными, отсутствие viewport доказуемо, сломанная мобильная верстка требует ручного браузерного теста. Вывод отсутствия сайта требует независимых доказательств и ручной проверки, никогда не делается по пустому полю.

## Надёжность и ресурсы
Атомарные уникальные ключи и leases; HTTP retries только для безопасных GET, источник exponential backoff; глобальный дневной лимит запросов, максимум 2 источника/тик, лимит новых уведомлений 3/тик, ограничение объёма. Однозначные ошибки Telegram повторяются; неопределённый результат sendMessage не повторяется автоматически. D1 outage → 503 webhook; Telegram повторяет доставку. Crash lease → восстановление. Пауза, аварийный /shutdown отключает уведомления и сбор. Retention 90 дней лидов, 30 дней сырых входящих; suppression hashes сохраняются до ручного снятия.

## Проверка
Unit классификации, бюджета, свежести, дедупликации, адресата/политики; integration D1/Worker/webhook/cron/outbox; реальные источники и аудит своего сайта read-only; тест Telegram только владельцу. Репозиторий, production, Telegram, следующий cron — отдельные критерии, нельзя считать выполненными без подтверждений.

## Запуск
Только Cloudflare Workers Free + D1 Free без карты и платной подписки; deploy guard проверяет account plan и требует 0-бюджет. CI GitHub только тесты; расписание живёт в Workers. Недостающие доступы: создание GitHub repository (текущий token createRepository denied), Cloudflare и Telegram secrets. Готовность описывается в CURRENT_STATE, незавершённое — TASK_QUEUE.
